# SQL_day03 — Continuing to JOIN and Modify Data (DML)

## О проекте
Этот проект посвящён углублённой работе с SQL-запросами, включающими не только извлечение данных, но и их изменение с помощью DML (INSERT, UPDATE, DELETE).  
В рамках проекта я решала задачи на основе реляционной модели данных, имитирующей работу сети пиццерий, клиентов, посещений и заказов.

Основной фокус — комбинирование сложных JOIN- и set-операций с безопасным и корректным изменением данных.

## Что я делала в этом проекте
В ходе выполнения заданий я:
анализировала реляционную модель и связи между сущностями (pizzeria, person, menu, visits, orders); писала сложные SELECT-запросы с JOIN, подзапросами и set-операциями (UNION, EXCEPT, INTERSECT); искала «потерянные» данные — меню без заказов, пиццы без покупателей, посещения без заказов; сравнивала поведение разных групп пользователей (по полу, датам, активности); выполняла модификацию данных через INSERT / UPDATE / DELETE с учётом целостности данных; реализовывала динамическую генерацию идентификаторов и дат (без хардкода); использовала паттерн `INSERT INTO ... SELECT ...` для массовых операций; откатывала изменения логически корректными DELETE-запросами.

## Ключевые навыки и темы
- Advanced JOINs и set-операции  
- Подзапросы и коррелированные запросы  
- Data Manipulation Language (INSERT / UPDATE / DELETE)  
- Генерация данных без жёстких идентификаторов  
- Работа с бизнес-логикой поверх SQL  
- Понимание UPDATE как DELETE + INSERT (реляционная теория)  
- Контроль консистентности данных при изменениях  

## Примеры решённых задач
- Поиск подходящих цен для конкретного клиента с учётом дат посещений  
- Обнаружение позиций меню, которые никогда не заказывались  
- Сравнение посещаемости и заказов между мужчинами и женщинами  
- Добавление новых позиций меню и автоматическое создание заказов  
- Массовое создание заказов для всех пользователей на основе генерации дат  
- Корректное удаление добавленных данных и восстановление состояния базы
